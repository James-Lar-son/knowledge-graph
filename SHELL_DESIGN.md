# Unified Shell — Design

Status: design for review (2026-10-16). Phase 1 cross-links are built; this
document covers the shell that turns the viewer + Taguette pair into one
application.

## The shape

One front door, two rooms:

- **Graph** — the public viewer (Render static site, this repo). Read,
  search, traverse; the memory of the system.
- **Code** — Taguette (Render web service, `Taguette-server` repo),
  enriched layer by layer. Where new evidence is coded into the graph.

Movement between them is by deep link, never by re-entry: viewer Source and
Evidence panels link into the exact Taguette document; Taguette's top bar
links back to the graph. Phase 1 (done) implements exactly this.

## Identity

- One name for the pair. Candidates: keep Taguette's configured instance
  name ("Larson Qualitative Coding") as the product name for both rooms, or
  name the graph side separately. Recommendation: one product name, two
  room labels — *Graph* and *Code* — shown in both nav bars.
- Shared visual tokens: the viewer's palette (dark panel `#1a1e23`, accent
  `#e0a458`) is the newer identity; Taguette's Bootstrap theme can adopt the
  accent via its `custom.css` static file, which the image patch mechanism
  can override the same way `base.html` was patched. Low effort, high
  "same app" signal.

## The shell page itself

Two candidate forms:

1. **Landing page (recommended first step).** A static page at the graph
   domain root path `/` successor — or a subdomain `kg.larsongrowth.com` —
   with: product name, the two room cards (Graph / Code) with live status
   (node/edge counts, last ingest date, Taguette up/down), and the current
   coding queue (sources in the manifest not yet coded). Generated by the
   same gated builder as the viewer, so status numbers are always true at
   build time. No JavaScript framework, no server.
2. **Frame shell.** One page embedding both apps in switchable panes.
   Rejected as the primary form: Taguette sends no embedding headers today,
   but cross-origin framing of an authenticated app is fragile (cookies,
   SameSite) and hurts mobile. Deep links in new tabs already give the
   side-by-side workflow. Keep as a possible desktop-only convenience
   later.

## Auth posture

- Graph room: public layer only, enforced at build time (leak gate). No
  login — by design, there is nothing private to protect.
- Code room: Taguette login; holds the *private* working material
  (documents pre-publication, the 2026 source). The private graph layer
  never crosses into the static build.
- Future option: a private full-graph viewer behind the Taguette login
  (served by the web service from the same disk) if James wants the
  quarantined layer browsable. Not built; the local full viewer covers
  this need today.

## Data flow (unchanged by the shell)

Canonical graph file (local, git-versioned) → gated builders → public
viewer. Taguette export → ingest staging → human approval → merge →
rebuild → push + API-triggered deploy. The shell adds no new write paths;
it is presentation over the existing loop. One operational fact learned
2026-10-16: pushes through the GitHub connector do **not** trigger Render
auto-deploy (no Render GitHub-app webhook on these repos), so each update
flow ends with an explicit API deploy trigger — or James installs Render's
GitHub app once in the dashboard to restore true auto-deploy.
