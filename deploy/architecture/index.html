The update loop

  1. James codes a document in Taguette, tagging spans with graph nodes.
  2. He exports the project; the ingest tool turns highlights into a staging report — new Evidence, new edges, proposed nodes.
  3. He reviews; on approval the merge writes to the canonical graph (the only write path in the system).
  4. Builders regenerate every page from the graph; the leak gate aborts if any quarantined material survives.
  5. Pages push to GitHub; a deploy is triggered through the Render API; the live pages are verified byte-for-byte.

Privacy model

Enforced at build time, never at display time. The public site is generated from a scrubbed copy of the graph: quarantined nodes and edges are removed, references to them are dropped, and a final scan aborts the build if any private ID or label remains. There is no login on this site because there is nothing private on it to protect. The private working material — unpublished documents and the quarantined layer — lives in Taguette (behind its login) and in the local canonical file.
